--- Key findings at 10.000 rows ---
1. Vietnamese_CI_AI folds tone marks (á = a) but NOT the letters ă â đ ê ô ơ ư: in the
   Vietnamese alphabet they are separate letters, so 'nguyen van a' never matches
   'Nguyễn Văn A' through the collation alone. ă/đ names are the common case, not an edge.
2. The same collation treats ng/nh/ch/th/ph/kh/gi/qu/tr as contractions: a 1-character
   prefix + wildcard returns 0 for 'Nguyễn'/'Châu'/'Thảo'/'Phạm'/'Khánh'/'Nhung'/'Giang'
   ('Nguyễn' LIKE 'n%' = 0, LIKE 'ng%' = 1). Names from 2 characters is therefore a
   CORRECTNESS rule, not only UX. Codes measured fine from 1 character.
3. NFD text pasted from Word does not match NFC data for ă ('Va'+breve ≠ 'Văn'); the app
   must normalize the search term to NFC (NormalizeForSearch).
4. Option (a) — a persisted HoTenKhongDau (diacritics stripped, đ→d, filled on save) with
   an index — satisfies AC1: the ASCII and accented queries return identical rows and the
   prefix query keeps an index seek (median 0,3 ms). Recommendation for Story 3.1/3.2.
5. Codes: MaSo prefix; a near-exact code seeks UQ_DoiTuongSpike_MaSo when the parameter is
   varchar (median 0,3 ms) and scans when it is nvarchar (EF default, median 3,3 ms).
   Names: HoTenKhongDau word-start (prefix seek for the first word,
   OR '% ' form scans at median 12,4 ms); contains scans at median 10,2 ms and is
   the last fallback.
6. Delegate the query to EF Core with the CancellationToken; cancellation aborts the SQL
   command (dm_exec_requests shows the request ending). Debounce 300 ms with
   cancel-previous keeps a fast typist at one visible query (slowest measured 340 ms).
